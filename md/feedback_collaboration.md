코드를 먼저 짜주지 말고 같이 짜야 한다. 급하거나 사용자가 명시적으로 요청할 때만 직접 작성.

**Why:** 사용자가 비즈니스 로직 훈련 중이며 코드 짜는 법을 배우고 싶어서. 운영 경력 6년 후 개발로 전향한 케이스라 하나하나 다 알고 가는 걸 선호함.

**How to apply:** 코드 설명 시 아래 방식으로 디테일하게 설명할 것:

- 함수/메서드가 뭔지 (어디서 온 건지, import 필요한지 등)
- 내장 함수면 어떤 기능을 하는 함수인지
- 각 인자가 뭘 의미하는지
- 다른 값을 넣으면 어떻게 되는지
- 실제 데이터 예시로 설명

예시: `process.exit(1)` 설명 시

- process가 뭔지 (Node.js 전역 객체, import 불필요)
- exit()이 뭘 하는지 (프로세스 강제 종료)
- (1)이 뭔지 (종료 코드, 0=정상, 1=비정상)
- 2를 넣으면 어떻게 되는지 (커스텀 에러 코드 가능하나 관례상 1 사용)

**parameter & 각종 인수,인자들**
아직 `()` 안에 들어가는 거 제대로 이해를 못 함. 함수 호출 시 인자 설명 필수 — 뭘 넣는지, 왜 그 값인지, 다른 값 넣으면 어떻게 되는지.

**값(value) vs 키(key) 구분:**
괄호 안에 들어가는 게 값인지 키인지 헷갈려함. 설명 시 명시 필수.

- `{}` 안에서 `key: value` 구조 — 왼쪽이 키, 오른쪽이 값
- `Object.entries(obj)` → `[key, value]` 쌍 배열로 분해
- `for (const [field, val] of ...)` — field가 키, val이 값
- 함수 인자도 마찬가지 — 어떤 타입의 데이터가 들어가는지 실제 예시로 설명

**왜 이렇게 짜는지:**
문법 설명하면서 "왜 이 방식을 선택하는지" (예: 왜 try-catch를 여기 쓰는지, 왜 이 위치에 미들웨어를 넣는지)
매서드에 대한 설명도 해줄 것, 왜 이 매서드를 사용했는지 이 매서드는 어떤 용도이고 어떻게 사용하는지

**기존 코드 패턴 따라가기 명시:**
새 기능 짤 때 프로젝트에 이미 있는 비슷한 패턴 먼저 찾아보고 그거 참고하라는 룰 — 일관성 있는 코드 베이스 만드는 습관.

**에러 메시지 읽는 법 우선 시도**
에러 나면 바로 답 주지 말고, 에러 메시지 읽고 어디서 났는지 먼저 찾아보게 유도 — 디버깅 근육 키우는 거.

**코드 리뷰 관점 추가**
완성된 코드 보고 "이 코드 면접에서 설명할 수 있는지" 자가 체크하는 습관 — 지금 하고 있는 것처럼.

**최종확인**
어떠한 에러도 용납이 안 됨, 해킹시도 들어올 거임
트래픽,메모리 누수 토큰 탈취, 어드민 보안, 미들웨어 검증 관련 검토

🔴 높음

- app/api/admin/login/route.ts — 어드민 로그인 쿠키(admin_token)에 secure: false가 박혀있어. HTTPS가 아닌 경로로 접근되는 경우(설정 실수 등) 이 쿠키가 그대로 스니핑당해서 어드민 권한을 통째로 탈취당할 수 있어. secure: true(또는 process.env.NODE_ENV === 'production')로 고쳐야 해.

🟡 중간 추가할 때 이 체크를 깜빡하면 무방비로 노출될 수 있어.

- admin/login — loginId/password 타입 검증 없이 바로 bcrypt.compare에 넣어서, 이상한 값 들어오면 500 에러가 남(내부 에러 노출 위험은 낮지만 정리 필요).

🟢 낮음

- 리뷰 "추천(feature)" API가 master 역할을 빼먹고 admin만 허용 — 다른 리뷰 API들과 권한 기준이 안 맞음.
- 일부 라우트에서 Number(id)가 NaN이 될 수 있는 경우 체크 누락(그냥 500 뜨고 끝, 악용은 안 됨).
- 레이트리밋이 메모리 기반이라 서버리스 인스턴스 여러 개 뜨면 우회 가능(트래픽 커지면 Redis로 전환 권장, 지금 규모엔 괜찮음).
- 이미지 업로드 개수 제한에 동시성(TOCTOU) 허점 있지만 어드민 전용이라 리스크 낮음.

✅ 문제 없음 확인된 것들

- 모든 admin API 라우트 인증 체크 완비, SQL Injection 없음($queryRaw 미사용), XSS는 매거진 HTML 렌더링 한 곳뿐인데 DOMPurify로 잘 막혀있음, ISR 캐시에 세션별 데이터 안 새고 있음, .env git에 안 올라감, 비밀번호는 전부 bcrypt(cost 12), 회원가입 시 이메일 중복 응답도 동일하게 나가서 이메일 탐지 공격 방지됨, 이미지 업로드 MIME/매직바이트/용량/압축폭탄 검증 다 있음, R2 키 경로 순회(path traversal) 불가능.
